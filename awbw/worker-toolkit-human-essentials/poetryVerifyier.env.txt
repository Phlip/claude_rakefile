  it. No Ruby is reachable from my shell: ruby, rake and jruby aren't on the
  PATH, and searching the filesystem didn't find your JRuby 9.4.5.0. So it's
  untested. Please run it from your own shell:

  rake task:verifier_env                              # every task under 
  harbor-tasks/
  rake "task:verifier_env[donation-new-cancel-button]"  # one task

  For each task it reads the [verifier.env] table in task.toml and checks:

  - Required keys: both ANTHROPIC_API_KEY and ANTHROPIC_BASE_URL are present.
    The grader needs both to reach the model API, and a missing one is marked ✘.
  - References, not values: each value should look like "${VAR}". A pasted-in
    literal value is marked ⚠ because it would ship inside the task (the
    credential-leakage detector cares about this).
  - Each variable resolves: each ${VAR} has a value in your shell, or failing
    that in the toolkit's .env. That's the same order scripts/harbor-run uses,
    since it sources .env. An unset variable is marked ✘.
  - Scaffold comparison: it lists any keys that differ from
    _task-scaffold/task.toml.

  Anything with "KEY", "TOKEN", "SECRET" or "PASSWORD" in its name is masked to
  its length and last four characters, so the key never appears in your
  terminal. The task ends with an error if anything was marked ✘, so you can
  chain it before task:run. Ruby has no built-in TOML parser, so I added a small
  reader that only handles flat KEY = "value" lines. That's all this table
  holds.

  Your current [verifier.env] matches the scaffold exactly. So when you run it,
  the only likely failure is the API key or base URL being unset in your shell
  or .env.
